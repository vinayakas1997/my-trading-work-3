# vinu-news - Issues Identified (2026-07-03)

## Overkill / Redundancy

### 1. Duplicate ticker extraction logic
**File:** `vinu_news/analysis/enrichment/ticker_extractor.py:51-68`

Falls back to hardcoded `DEFAULT_MAJOR_TICKERS` (AAPL, GOOGL, MSFT, etc.) when <5 tickers found, then uses `ticker_db.py` for aliases. The hardcoded set is stale and creates unnecessary complexity — alias lookup should use the watchlist (or already-extracted tickers) directly.

### 2. Dead code: article_matches_watchlist
**File:** `vinu_news/collection/filter.py:28-35`

`article_matches_watchlist()` is identical to logic in `filter_leads_for_mode()` but is never called in production code.

### 3. Excessive enrichment stages
**File:** `vinu_news/analysis/enrichment/enrich.py`

All 9 enrichment stages (priority, sentiment, impact, category, tickers, language, threat, source_flag, summary_clean) + ticker dominance run on every article. No opt-out mechanism. Stages like `threat` and `language` may be unnecessary for basic RSS aggregation.

## Potential Gaps

### 4. Duplicate ingestion methods
**File:** `vinu_news/service.py:330-511`

`run_ingestion_cycle()` and `run_ticker_news_ingest()` share 90% identical logic (enrichment, filtering, persistence). Only the fetch phase differs. Adding new sources (FMP) would require further duplication.

### 5. skip_post_process flag with no clear use case
**File:** `vinu_news/service.py:214`

The `skip_post_process` flag bypasses NER, cosine dedup, and lead selection — storing duplicates. No documented reason for keeping duplicates.

### 6. Auto-analysis threading without rate limiting
**File:** `vinu_news/service.py:29-52`

Spawning a `ThreadPoolExecutor` per ingest cycle could overwhelm the LLM if many articles arrive. No queue, no backpressure, no limit on concurrent threads spawned across cycles.

### 7. Dual settings sources
**Files:** `vinu_news/config.py`, `vinu_news/settings/store.py`

`llm_analysis_mode` and `llm_analysis_concurrency` exist in both `.env` (via `VinuConfig`) and the DB settings table. After first run, changing `.env` has no effect — the DB owns them. This creates confusion.

## Minor Issues

### 8. MAX_WORKERS hardcoded
**File:** `vinu_news/rss/config/settings.py`

`MAX_WORKERS = 8` is hardcoded and doesn't adapt to system resources or allow user configuration.

### 9. Hash collision risk
**File:** `vinu_news/analysis/enrichment/enrich.py:24`

`article_id_from_link()` uses SHA256 of URL only. While collisions are astronomically unlikely, no fallback mechanism exists if one occurs.
