## Phase 1: Critical — Storage Concurrency & Safety

**Goal:** Fix race conditions, thread safety, and atomic claiming in SQLite.

### 1.1 Atomic `claim_next_pending` (Issue #1)

**Files:** `vinu_features/storage/sqlite_backend.py:190-216`, `vinu_features/worker/runner.py:41-51`

**Current:** Two separate operations — `SELECT` then `UPDATE` — with a gap where another worker can claim the same request.

**Fix:** Merge into a single atomic `UPDATE ... RETURNING *`:

```python
# sqlite_backend.py
def claim_next_pending(self) -> FeatureRequest | None:
    now = utc_now_iso()
    row = self._conn.execute(
        """
        UPDATE feature_requests
        SET status = ?, updated_at = ?, error_message = NULL
        WHERE id = (
            SELECT id FROM feature_requests
            WHERE status = ?
            ORDER BY created_at ASC
            LIMIT 1
        )
        RETURNING *
        """,
        (STATUS_RUNNING, now, STATUS_PENDING),
    ).fetchone()
    self._conn.commit()
    if row is None:
        return None
    return FeatureRequest.from_row(dict(row))
```

Then simplify `process_pending` in `worker/runner.py` since `claim_next_pending` now atomically transitions to `running`:

```python
def process_pending(self, *, limit: int = 1) -> list[FeatureRequest]:
    results: list[FeatureRequest] = []
    for _ in range(limit):
        running = self.storage.claim_next_pending()
        if running is None:
            break
        results.append(self._execute(running))
    return results
```

### 1.2 Thread-local SQLite connection (Issue #2)

**File:** `vinu_features/storage/sqlite_backend.py:55`

**Fix:** Replace single `_conn` with thread-local connections:

```python
import threading

class SqliteBackend:
    def __init__(self, db_path: Path) -> None:
        self.db_path = Path(db_path)
        self.db_path.parent.mkdir(parents=True, exist_ok=True)
        self._local = threading.local()
        self._init_connection()

    def _get_conn(self) -> sqlite3.Connection:
        conn = getattr(self._local, "conn", None)
        if conn is None:
            conn = sqlite3.connect(str(self.db_path))
            conn.row_factory = sqlite3.Row
            conn.execute("PRAGMA journal_mode=WAL")
            conn.executescript(_SCHEMA)
            self._local.conn = conn
        return conn
```

Remove `check_same_thread=False`. Each thread gets its own connection.

## Phase 3: Performance — Rolling & Alpha Computation

**Goal:** Fix O(n×w) hot loops and parallelize symbol fetching.

### 3.1 Optimise `rolling_std` (Issue #6)

**File:** `vinu_features/compute/indicators/_shared/rolling.py:34-43`

**Fix:** Use a list-based window that avoids creating a filtered list per iteration:

```python
def rolling_std(values: list[float | None], period: int) -> list[float | None]:
    result: list[float | None] = [None] * len(values)
    if period <= 0:
        return result
    window: list[float] = []
    for i, v in enumerate(values):
        if v is not None:
            window.append(v)
        else:
            window.clear()
            continue
        if len(window) > period:
            window.pop(0)
        if len(window) == period:
            mean = sum(window) / period
            var = sum((x - mean) ** 2 for x in window) / period
            result[i] = math.sqrt(var)
    return result
```

### 3.3 Optimise alpha rolling functions with `np.lib.stride_tricks` (Issue #7)

**File:** `vinu_features/compute/bigger_recipe/_alpha_expr/evaluator.py:111-128`

**Fix:** Replace `_rolling_apply` with NumPy sliding window view:

```python
def _rolling_apply(arr: np.ndarray, w: int, fn) -> np.ndarray:
    out = np.full_like(arr, np.nan, dtype=float)
    n = len(arr)
    if n < w:
        return out
    windows = np.lib.stride_tricks.sliding_window_view(arr, w)
    mask = ~np.any(np.isnan(windows), axis=1)
    if mask.any():
        out[w - 1:][mask] = [fn(w) for w in windows[mask]]
    return out
```

Apply the same pattern to `_rank`, `_quantile`, `_slope`, `_rsquare`, `_resi`, `_idxmax`, `_idxmin`, `_corr`.
