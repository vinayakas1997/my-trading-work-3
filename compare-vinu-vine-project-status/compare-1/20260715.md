# Project Comparison & Evolution Report: Vibe-Trading vs. vinu-components
**Date**: July 15, 2026

## 1. Executive Summary

This document captures the comparative landscape between the legacy reference repository **Vibe-Trading** (v0.1.11, ~203k LOC Python, MIT, HKUDS) and the current state of **vinu-components** (~15k LOC across 7 microservices).

Vibe-Trading is a feature-rich monolith with production trading infrastructure — larger "muscles" by every feature count. vinu-components has been engineered with a modern microservices architecture — a cleaner "skeleton." The gap is real but bridgeable:

- Vibe-Trading covers **10-15x more** trading infrastructure (data sources, backtest engines, broker connectors, live trading, frontend, 16 IM channels)
- vinu-components wins on **architecture quality** (microservices, security library, resilient client, domain separation, iteration velocity)

The strategic path forward (Phase A of `vinu-agent`) is the right approach — build the agent layer on our clean foundation rather than trying to copy Vibe-Trading's monolith.

## 4. What is Superior in Our Project

### Architecture
- **Microservices**: 7 independently deployable services with clear REST API boundaries. A crash in `vinu-features` cannot bring down the simulator or database. Vibe-Trading's monolith has no such isolation.
- **Domain separation**: `vinu-stock-price`, `vinu-features`, `vinu-simulator`, `vinu-research`, `vinu-strategy`, `vinu-correlation`, `vinu-news` — each with its own `pyproject.toml`, test suite, and deployable artifact. Vibe-Trading has everything under `agent/src/` organized by function.

### Security Library
- `vinu-lib/security/` is a single importable Python package with `scanner.py` (prompt injection, 5 rules), `network.py` (SSRF guard with private network validation). Every service imports it. Vibe-Trading spreads security across `agent/src/security/`, `agent/src/api/security.py`, and `agent/backtest/runner.py`.

### Resilient Client
- `vinu-lib/ResilientClient` integrates circuit breaker (`CircuitBreaker` with closed/open/half-open states), automatic retry with exponential backoff, and SSRF guard (`validate_url_target`) into a single async HTTPX-based client. Vibe-Trading duplicates retry/breaker logic across different call sites.

### Ease of Agent Instrumentation
- Because our platform consists of 7 independent RESTful services, each with a focused API surface, an LLM agent can interact with them via simple HTTP calls. No need to parse complex internal Python classes or navigate a large monolith. This is why the `vinu-agent` Phase A plan maps cleanly to 7 tool definitions.

### Iteration Velocity
- Per-service tests compile and run in milliseconds. Full test suite across all 7 services completes in seconds. Vibe-Trading's 203k LOC monolith with 256 test files takes much longer.

## 5. Strategic Path Forward

Instead of copying Vibe-Trading's monolithic approach, we will bridge the feature gap by building **`vinu-agent`** alongside our existing services:

1. **No Breaking Changes**: The existing 7 services remain clean and untouched. All CLI commands continue working.
2. **Phase A — Agent Core**: Build the ReAct reasoning engine (`AgentLoop`, `ToolRegistry`, `ContextBuilder`, 5-layer context management) as a new `vinu-agent` service on port 8086.
3. **Phase B — Session Management**: Persistent conversations with SSE streaming (`SessionStore`, `EventBus`, `SessionService`).
4. **Phase C — Skills System**: Progressive-disclosure skill library as Markdown files with YAML frontmatter.
5. **Phase D — Swarm Orchestration**: DAG-based multi-agent orchestration with YAML presets.
6. **Phase E — IM Channels**: Telegram/Discord adapters.
7. **Phase F — Persistent Memory + Config**: Cross-session memory and Pydantic-based env config.

The 7 services as agent tool mapping:
- `vinu-simulator` → `run_backtest` tool
- `vinu-features` → `get_features` tool
- `vinu-stock-price` → `get_stock_price` tool
- `vinu-news` → `get_news` tool
- `vinu-correlation` → `get_correlation` tool
- `vinu-strategy` → `run_strategy` tool
- `vinu-research` → `run_research` tool
