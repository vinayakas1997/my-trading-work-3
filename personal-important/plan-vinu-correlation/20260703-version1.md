# vinu-correlation: Design Plan (v2 — Audit-Updated)

Date: 2026-07-03

---

## Vision

The bridge between `vinu-news` and `vinu-stock-price` that mathematically proves news impact on price movements. The Risk Critic Agent calls `vinu_correlation.get_impact("AAPL")` and gets back structured evidence like `{"high_impact_bearish_events": 4, "avg_price_drop_30m": -1.2%}`.

## Existing Foundations

- `vinu-news/price_reaction.py` — computes 1h/1d price change per article, SQLite cache. Good starting point but only point-in-time, no statistics.
- `ref-fincept-terminal/news_correlation.py` — signal detection patterns (z-score deviations, velocity spikes, triangulation). Useful patterns to adapt.
- Both `vinu-news` and `vinu-stock-price` have clean HTTP APIs ready to consume.
- `vinu-news/articles` table already has `sentiment`, `sentiment_score`, `impact` fields populated during ingestion.
- `vinu-news/article_price_reaction` table already has precomputed `price_change_1h` and `price_change_1d` per article.

## Deployment Model: Standalone Microservice

Follows the existing `vinu-*` pattern with its own FastAPI server, Dockerfile, and `pyproject.toml`. Calls `vinu-news` and `vinu-stock-price` HTTP APIs as data sources.

## Storage Model: Parquet

Like `vinu-stock-price`, store correlation time-series as Parquet files queryable via DuckDB.

**Path convention:**
```
{data_root}/correlation/{SYMBOL}/{YYYY}.parquet           # impact events
{data_root}/correlation/{SYMBOL}/{YYYY}_baseline.parquet  # rolling baselines
```

## Impact Windows: 1h / 1d (start)

Reuse existing `price_reaction.py` logic for 1h and 1d windows. Add finer windows (5m, 15m, 30m) later when needed.

## HTTP Client Pattern (`net.py`)

Extend the existing `vinu-news/net.py` pattern with timeout and retry:

```python
def request(method, url, *, timeout=30, retries=3, **kwargs):
    """HTTP request with timeout, retry, and Docker loopback fallback."""
    for attempt in range(retries):
        try:
            return requests.request(method, url, timeout=timeout, **kwargs)
        except requests.ConnectionError as e:
            if "Connection refused" not in str(e) or attempt == retries - 1:
                if attempt == 0:
                    fallback = _docker_fallback_url(url)
                    if fallback:
                        url = fallback
                        continue
                raise
            time.sleep(1 * (2 ** attempt))  # exponential backoff
```

## API Endpoints (FastAPI)

Response envelope: `{count: int, data: list[dict]}` (DataResponse) for list endpoints.

| Endpoint | Returns | Agent Usage |
|----------|---------|-------------|
| `GET /health` | `{ok: true}` | Liveness check |
| `GET /impact/{ticker}?from=&to=` | `DataResponse[{headline, ts, sentiment, impact_label, price_change_1h, price_change_1d}]` | Risk Critic: "Did news cause this drawdown?" |
| `GET /events/{ticker}?from=&to=` | `DataResponse[{headline, ts, sentiment, impact_label, price_change_1h, price_change_1d}]` | Debug: list all news events with impact |
| `GET /correlation/{ticker}?from=&to=` | `{news_return_corr, sentiment_return_corr, news_volume_corr, best_lag_minutes}` | Statistical proof of news impact |
| `GET /drawdown/{ticker}?from=&to=` | `{drawdowns: [{peak_ts, trough_ts, drop_pct, news_caused, primary_headlines[]}]}` | Drawdown attribution |
| `GET /baseline/{ticker}` | `{mean_daily_articles, stddev, z_score, deviation_level}` | "Is news volume abnormally high?" |
| `GET /settings` | Current thresholds and config | Debug/config |
| `PATCH /settings` | Updated thresholds | Runtime tuning |

## Engine Modules

### 1. `engine/impact.py` — Per-News-Event Impact

- Fetch articles from `vinu-news` via `GET /articles/since?since_ts={from}&until_ts={to}`
- For each article with tickers: fetch candles from `vinu-stock-price` via `GET /candles/{symbol}?from={sort_ts}&to={sort_ts+86400+3600}`
- Compute `price_change_1h` and `price_change_1d` (reuse algorithm from `price_reaction.py:compute_price_changes`)
- Classify each event based on configurable thresholds:
  - `high_bearish`: sentiment=BEARISH AND |change| >= impact_high_threshold
  - `high_bullish`: sentiment=BULLISH AND |change| >= impact_high_threshold
  - `medium`: |change| >= impact_medium_threshold
  - `low`: |change| < impact_medium_threshold
- Write results to Parquet: `{data_root}/correlation/{SYMBOL}/{YYYY}.parquet`
- **Reuse note:** Can read precomputed `price_change_1h`/`price_change_1d` from `vinu-news`'s `article_price_reaction` table to avoid redundant computation. Only fetch fresh candles for articles without cached reactions.

### 2. `engine/correlation.py` — Time-Series Correlation

- Resample news into 1h buckets: article count, avg_sentiment, avg_impact_score per bucket
- Resample price into 1h returns: `(close_t+1h - close_t) / close_t`
- Align the two time series on matching timestamps
- Compute Pearson correlation between news features and forward returns
- **Lag analysis:** shift news series 15m, 30m, 1h forward; report `best_lag_minutes` where correlation peaks
- Store aggregated correlation matrices in Parquet

### 3. `engine/drawdown.py` — Drawdown Attribution

- Scan price series for peak-to-trough drawdowns > `drawdown_min_pct` (default -3%)
- For each drawdown, check the preceding `drawdown_lookback_hours` (default 24h) for high-impact news events
- Classify:
  - `news_caused`: high-impact news present in lookback window
  - `unexplained`: no significant news in lookback window
- Return structured evidence with primary headlines for the Risk Critic Agent

### 4. `engine/baseline.py` — Deviation Detection

- 7-day rolling hourly article count per ticker (adapted from Fincept's `news_correlation.py:baseline_update`)
- Z-score: `(current - mean) / stddev`
- Flag deviations: `normal` (z<2), `elevated` (2-3), `high` (3-4), `critical` (>4)
- Store baselines in `{data_root}/correlation/{SYMBOL}/{YYYY}_baseline.parquet`

## Key Design Decisions (Confirmed)

1. **Deployment:** Standalone microservice (own FastAPI, Dockerfile, pyproject.toml)
2. **Storage:** Parquet files (DuckDB queryable), path: `{data_root}/correlation/{SYMBOL}/{YYYY}.parquet`
3. **Impact windows:** Start with 1h/1d only, add finer granularity later
4. **Data sources:** HTTP clients to vinu-news and vinu-stock-price APIs
5. **Consumers:** Risk Critic Agent (primary), human debug (secondary)
6. **vinu-agents dependency:** Graceful fallback to existing `articles.sentiment` field
7. **HTTP resilience:** timeout=30, 3 retries with exponential backoff, Docker loopback fallback
8. **CLI:** argparse (matching existing vinu-* pattern), not Click
9. **Response format:** `{count, data}` DataResponse envelope (matching existing services)
10. **Reuse:** Read precomputed `price_change_1h`/`price_change_1d` from `article_price_reaction` when available
