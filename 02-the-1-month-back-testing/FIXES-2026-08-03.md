# Fixes — 2026-08-03 — what was changed, precisely, and why

**Status:** all verified against the running `vinu-components` stack and the
1-day replay smoke test. These are the exact changes made today, in order, so
there is no ambiguity later about "what did we fix and why."

This documents two **data-path** fixes in the agent's tool layer that the
previous `TOOL-CALLING-BUG-FINDINGS.md` did not cover. The earlier doc covered
the schema-wrapping (Bug 1) and URL-prefix (Bug 2) fixes; this covers what the
v3 smoke test (`results/schema-and-url-fix-smoke-test-v3/`) then exposed: even
with valid schemas and correct URLs, `get_features` and `get_news` returned
empty/error data during replay, leaving the agent blind on 2 of its 3 research
tools.

---

## Fix 1 — `get_features` returned `422 Unprocessable Entity` every time

### What was wrong
- **Agent side** (`vinu-agent/vinu_agent/tools/features_tool.py`): the tool
  POSTed `{symbol, indicators, from_ts, to_ts}` to `POST /features/requests`.
- **Server side** (`vinu-tools/vinu_tools/server/schemas.py:17`,
  `FeatureRequestIn`): the API requires `{title, symbols, from_ts, to_ts,
  features/preset, run_immediately}` — `symbol` and `indicators` do not exist
  in the schema.
- **Result:** FastAPI rejected every call with 422. Confirmed live in the v3
  smoke-test trace (step 7: `Client error '422 Unprocessable Entity' for url
  'http://features-api:8082/features/requests'`). The agent therefore could
  not compute **any** technical indicator during replay.

### Why fixing the payload alone wasn't enough
Even with a correct payload, the POST returns a request **metadata** object
(`id`, `status`, `row_count`, `file_path`) — not the computed rows. The
parquet lives at `file_path` inside the features-api container's volume
(`./data/features:/data`), which the agent container does not mount. So the
agent needed an HTTP path to read the computed values, which did not exist.

### What was changed
1. `vinu-tools/vinu_tools/service.py` — added `get_request_data(request_id)`
   which loads the done request's `features.parquet` and returns rows as
   JSON records (`{"count", "status", "data"}`).
2. `vinu-tools/vinu_tools/server/routes_requests.py` — added
   `GET /features/requests/{request_id}/data` calling the service method
   (404 for unknown/missing file, 500 on other errors).
3. `vinu-agent/vinu_agent/tools/features_tool.py` — rewrote `execute()`:
   - builds a request with the correct schema
     (`title`, `symbols=[symbol]`, `from_ts`, `to_ts`, `features=indicators`,
     `run_immediately=true`),
   - if status != "done", returns the error payload,
   - otherwise GETs `/{request_id}/data` and returns those rows.

### Files changed
- `vinu-components/vinu-tools/vinu_tools/service.py`
- `vinu-components/vinu-tools/vinu_tools/server/routes_requests.py`
- `vinu-components/vinu-agent/vinu_agent/tools/features_tool.py`

### Verification (run, passed)
- `curl -X POST .../features/requests` with the new payload → `id`, status
  `done`, `row_count: 20`.
- `curl .../features/requests/2/data` → `{"count": 20, "status": "done",
  "data": [...]}` with real AAPL OHLCV rows.
- Smoke test v4 (`results/features-news-fix-smoke-test/2026-07-06/thinking.json`,
  step 10) — the agent's `get_features` call returned 18 real rows including
  `rsi_14` values; the agent's own summary quoted "RSI at 56.7" from that data.

## Fix 2 — `get_news` returned 0 articles whenever the agent omitted `start_date`

### What was wrong
- `vinu-agent/vinu_agent/tools/news_tool.py` clamps `to` to `_as_of`
  (replay date, e.g. 2026-07-06) but sent **no `from`** when the LLM didn't
  provide a `start_date`.
- `vinu-news/vinu_news/service.py:706` `get_ticker_news()` falls back to
  `self.ts_days_ago(7)` when `from_ts is None`, and `ts_days_ago()` uses
  **real wall-clock now** (`service.py:684`, `datetime.now(timezone.utc)`).
- During replay, real now = 2026-08-03 → fallback start = 2026-07-27, which is
  **after** the clamped `to` (2026-07-06). Inverted range → 0 rows.
- **Result:** in the v3 smoke test the agent called news without a
  `start_date` and got `{"count": 0, "data": [], "clamped_end_to_as_of": true}`
  for AAPL — even though 168 AAPL articles exist in that window — and the
  agent concluded "No news available for AAPL."

### Why it matters
News is one of the agent's core research inputs (alongside price and
fundamentals). A replay where news silently returns empty makes the agent
decide on partial information, which item 5's behavioral rubric would then
misattribute to bad judgment instead of a data bug.

### What was changed
- `vinu-agent/vinu_agent/tools/news_tool.py` — in `execute()`, when
  `_as_of` is set and no `start_date` was provided, derive `from_epoch =
  to_epoch - 30*86400` (30-day lookback anchored to the replay date, never to
  wall-clock). The service's real-now fallback is therefore never reached in
  replay mode.

### Files changed
- `vinu-components/vinu-agent/vinu_agent/tools/news_tool.py`

### Verification (run, passed)
- `docker exec .../news-api` calling `get_ticker_news('AAPL',
  from_ts=to-30d, to_ts=as_of)` → 20 articles (was 0).
- Inside the rebuilt agent container, `NewsTool().execute(symbol='AAPL')`
  with `_as_of='2026-07-06T13:30:00Z'` → `{"count": 20, ...}` with real AAPL
  headlines (e.g. "Broadcom Stock Climbs on Report of Apple Chip Deal").

## How to re-verify quickly (no LLM needed)

```bash
cd vinu-components
# features: create + read back
curl -s -X POST http://localhost:8082/features/requests -H 'Content-Type: application/json' \
  -d '{"title":"verify","symbols":["AAPL"],"from_ts":1783296000,"to_ts":1785542400,"features":["sma_20","rsi_14"],"run_immediately":true}'
# → id + "status":"done"
curl -s http://localhost:8082/features/requests/<id>/data   # → rows with real values

# news replay path (in the agent container, so _as_of is set)
docker compose exec -T agent-api python3 -c "
from vinu_agent.tools.news_tool import NewsTool
t = NewsTool(); t._services_config={'vinu_news':'http://news-api:8080'}; t._as_of='2026-07-06T13:30:00Z'
print(t.execute(symbol='AAPL')[:200])"   # → count 20, not 0
```
