## Issue I4-1 — Context manager leaves closed service accessible (MEDIUM)

**Location:** `vinu_simulator/api.py`, `SimulatorAPI.__exit__`

**Problem:** `__exit__` calls `self._service.close()` but never sets `self._service = None`.
After the context manager exits, any subsequent call to `simulate()`, `list_runs()`, etc.
transparently reuses the already-closed service, which will fail because:
- `httpx` transport is closed (dead connections to upstream APIs)
- SQLite connections are closed (all reads/writes fail)

**Symptoms:** Hard-to-debug runtime errors when using the API as a context manager.

**Root cause:** Missing cleanup of the cached reference after closing.

## Issue I4-2 — Dead assignment before sell loop (LOW)

**Location:** `vinu_simulator/engine/simulator.py`
- `WeightSimulator.run()` — line 128
- `SimulatorEnv.step()` — line 306

**Problem:** `target_values = nav_before * rebalance_weights` is computed before the sell loop,
but this value is **never read** — it is unconditionally overwritten after the sell loop
(run line 163, step line 329) before any use.

```python
# Run (line 128) — DEAD, overwritten at line 163
target_values = nav_before * rebalance_weights

# ... sells happen, cash/holdings change ...

# Run (line 163) — this is the real assignment
nav_after_sells = cash + np.sum(holdings * prices)
target_values = nav_after_sells * rebalance_weights
```

**Impact:** None — the compiler/interpreter discards it. However, it is misleading and
suggests the author intended to use the pre-sell `target_values` somewhere.

## Issue I4-3 — `step()` silently swallows NaN/Inf deviation (LOW)

**Location:** `vinu_simulator/engine/simulator.py`, `SimulatorEnv.step()`

**Problem:** When `deviation` is NaN or Inf, `run()` explicitly `continue`s (exit the iteration),
but `step()` uses a bare `pass`. While both skip rebalancing, the silent pass
in `step()` means:
- No evidence of the bad state is recorded or raised.
- The step still progresses to the next date, revalues the portfolio at stale holdings,
  and records potentially incorrect equity/reward.
- This is inconsistent with how every other NaN/Inf case is handled in both methods
  (prices, shares_to_sell, shares_to_buy all raise `ValueError`).

```python
# The inconsistency:
if not np.isfinite(deviation):
    pass   # step() — silent, no indication of bad data
```

```python
if not np.isfinite(deviation):
    continue  # run() — explicit skip
```
