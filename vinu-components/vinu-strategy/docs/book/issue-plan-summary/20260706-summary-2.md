# vinu-strategy: Version 2 Summary

Date: 2026-07-06

---

## Overview

Version 2 addressed 6 issues in the vinu-strategy codebase — enhancements building on the v1 bugfixes. All changes implemented, tested (64/64 tests passing), and verified with runtime integration tests.

---

## Changes Made

### 1. Risk stage handles negative weights (short signals)

- **`risk.py`**: Rewrote `risk_normalize` to separate long (positive) and short (negative) positions. Each is capped independently (`max_weight` for longs, `max_short_weight` for shorts). Gross exposure (`sum(longs) + abs(sum(shorts))`) is calculated, and if it exceeds `1 - cash_floor`, both sides are scaled proportionally. Added per-strategy `allow_short` flag — when `False`, negative weights are clipped to zero.
- **`pipeline.py`**: Passes `allow_short`, `max_short_weight` from YAML `risk.params` through to `risk_normalize`.
- **Tests**: 7 new tests in `test_risk.py` covering mixed long/short, capped shorts, scaled shorts, and `allow_short: false`.

### 2. Expression evaluator case sensitivity

- **`expression.py`**: Added `_CaseInsensitiveContext` class wrapping the evaluation context. `get(key)` tries in order: original → lowercase → uppercase. This ensures expressions like `SMA_9` match regardless of how the API returns the key.
- **`service.py`**: Updated `_extract_feature_values` to normalize all API-returned keys to lowercase before storing in the context dict.

### 3. YAML schema validation

- **`strategy.py`**: Added known-key whitelists for every YAML section (top-level, pipeline config, each pipeline stage). `StrategyConfig.from_dict()` now logs warnings via `_warn_unknown_keys()` for any unrecognized keys.
- **`registry.py`**: Passes the YAML file path as `source` so validation warnings include the originating file.
- **Tests**: Added `test_yaml_validation_unknown_top_level_keys` and `test_yaml_validation_unknown_method` in `test_registry.py`.

### 4. Parquet per-day file storage

- **`weights.py`**: Changed from a single `{year}.parquet` file to per-day files at `{strategy}/{year}/{month:02d}/{day:02d}.parquet`. New `append_weights` call writes to a separate file — O(1) per write instead of O(n). `_collect_tables` reads all day-files and concatenates. `delete_weights` walks the directory tree, removing individual day-files and cleaning up empty directories.
- **Backward compatibility**: Old per-year files are no longer read by `_collect_tables`. Since the project is v0.1.0, no migration path is provided.

### 5. DELETE endpoints

- **`routes_read.py`**: Added `DELETE /weights/{strategy}`, `DELETE /runs`, `DELETE /runs/{run_id}` endpoints.
- **`api.py`**: Corresponding `delete_weights`, `delete_runs`, `delete_run_by_id` methods.
- **`service.py`**: Delegates to storage layer.
- **`weights.py`**: `delete_weights` supports per-symbol deletion (filtered rewrite) or full strategy deletion (file removal + empty directory cleanup).
- **`meta.py`**: `delete_runs` and `delete_run_by_id` methods for run metadata.

### 6. Scheduler for auto-evaluation

- **`cli.py`**: Added `vinu-strategy schedule` subcommand. Loads all registered strategies and their `schedule` interval (hourly/daily/weekly/monthly). Polls every 60 seconds, evaluates any strategy whose configured interval has elapsed since last run. Uses simple `time.sleep(60)` loop — no external dependency on APScheduler.
- **No API endpoint** for scheduler status (deferred to v3).
