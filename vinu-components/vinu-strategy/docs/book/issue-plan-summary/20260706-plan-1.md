## Plan 1.1: Fix `select_threshold` field parameter

**Files to modify:**
- `vinu_strategy/engine/selection.py`
- `vinu_strategy/engine/pipeline.py`
- `tests/test_selection.py`

**Approach:**
1. Change `select_threshold` signature to accept `signal_context` parameter
2. When `field != "signal"` and `signal_context` is available, look up `signal_context[sym]["features"].get(field, 0.0)` for comparison
3. Fall back to `signals.get(sym, 0.0)` when field is "signal" or context is missing
4. Pass `signal_context` from pipeline's `run()` method to `run_selection()`
5. Add tests for field-based threshold filtering

## Plan 1.2: Implement signal expression evaluator

**New file:** `vinu_strategy/engine/expression.py`

**Files to modify:**
- `vinu_strategy/engine/allocation.py`
- `vinu_strategy/engine/pipeline.py`
- `tests/test_allocation.py`
- `tests/test_expression.py`

**Approach:**
1. Create a safe AST-based expression evaluator supporting: `+`, `-`, `*`, `/`, `**`, `%`, parentheses, and built-in functions `max`, `min`, `abs`, `round`
2. Validate AST tree to reject dangerous nodes (function calls other than allowed, attribute access, etc.)
3. Update `allocate_signal_scaled` to check for a `signal` param and evaluate it per-symbol using signal_context
4. Preserve the sign of the expression result (unlike the original `abs()` behavior for aggregated signals)
5. Pass `signal_context` from pipeline to allocation
6. Add comprehensive tests
