# vinu-strategy: Version 3 Issues (Enhancements)

Date: 2026-07-06

---

## Issue 3.1: No `--verbose` / `--log-level` CLI flag

**File:** `vinu_strategy/cli.py:151`

**Problem:** `logging.basicConfig(level=logging.WARN)` is hardcoded. There is no way to see INFO or DEBUG output without modifying source code. When debugging strategy evaluation or API connectivity issues, users must add print statements or change the log level manually.

**Impact:** Developer experience. Requires code modification to diagnose issues.

---

## Issue 3.2: No health check endpoint

**Files:** `vinu_strategy/server/routes_read.py`, `vinu_strategy/server/routes_config.py`

**Problem:** The FastAPI server has no `GET /health` or `GET /ping` endpoint. For container orchestration (Kubernetes liveness/readiness probes), load balancer health checks, and monitoring, a lightweight health endpoint is standard practice.

**Impact:** Cannot integrate with container orchestration or automated health monitoring.

---

## Issue 3.3: No retry logic in API clients

**File:** `vinu_strategy/clients/base.py`

**Problem:** The `BaseClient.get()` method catches `httpx.RequestError` and returns `{}` on any failure. There is no retry mechanism. Transient failures (network blips, service restarts, timeouts) are silently absorbed as empty data, potentially producing incorrect weights.

**Impact:** Silent data loss on transient API failures. No resilience for intermittent outages.

---

## Issue 3.4: No strategy CRUD via API

**Files:** `vinu_strategy/server/routes_read.py`, `vinu_strategy/server/routes_config.py`

**Problem:** Strategies are managed exclusively through YAML files on disk. There is no `POST /strategies`, `PUT /strategies/{name}`, or `DELETE /strategies/{name}` endpoint. Users cannot create, update, or delete strategies at runtime through the API.

**Impact:** Requires filesystem access to manage strategies. Not suitable for multi-tenant or API-only deployment.

---

## Issue 3.5: Stale data persists when strategies are deleted

**Files:** `vinu_strategy/storage/weights.py`, `vinu_strategy/storage/meta.py`

**Problem:** When a strategy YAML file is removed from the strategies directory, the corresponding weight Parquet files and run metadata remain in the data directory indefinitely. There is no cleanup mechanism tied to strategy lifecycle.

**Impact:** Orphaned data accumulates over time. Users must manually clean up storage directories.

---

## Issue 3.6: Web UI could show richer evaluation results

**File:** `web/src/components/StrategyDashboard.jsx`

**Problem:** The Evaluate Now response returns weights with `signal_value`, but the UI does not display intermediate pipeline stage outputs (e.g., pre-risk weights, per-feature signal breakdowns, rule trace). Users cannot inspect why a particular weight was assigned.

**Impact:** Limited debugging visibility in the UI. Users must use the CLI `--trace` and `--json` flags to debug.
