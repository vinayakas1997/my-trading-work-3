# vinu-stock-price Fix Plan

**Date:** 2026-07-03
**Source:** `20260703-issue.md` (25 issues identified)

---

## Phase 1 — Performance (High Impact, Low Risk)

### P1.1 — Parquet partition pruning
- **Issue #2:** DuckDB scans all parquet files regardless of time range
- **Fix:** Use `parquet_globs_by_range` (already exists in `paths.py`) instead of `parquet_globs` in `fetch_candles`. Pass `from_ts`/`to_ts` to dynamically build year-scoped file lists.
- **Files:** `vinu_stock/query/engine.py`, `vinu_stock/storage/paths.py`

### P1.2 — `data_root` SQLite round-trip
- **Issue #6:** Every call triggers a SQLite query
- **Fix:** Cache `data_root` in `__init__` as `self._data_root` by calling `self._backend.get_settings().data_root` once. Remove the `@property` and use the cached field directly. Add a `reload()` method or update the cache when `patch_settings` changes `data_root`.
- **Files:** `vinu_stock/service.py`

### P1.3 — `aggregate_bars` redundant double sort
- **Issue #3:** DuckDB already returns rows ordered, but code sorts twice
- **Fix:** For the 1m case, skip `sorted()` entirely. For higher intervals, remove `sorted()` on `rows` (trust DuckDB order).
- **Files:** `vinu_stock/query/aggregate.py`

### P1.4 — `_rolling_std` O(n×period) list allocations
- **Issue #4:** Allocates a new filtered list per window position
- **Fix:** Replace list comprehension per window with a sliding deque tracking count of non-None values. Maintain `sum`, `sum_sq` for O(1) variance per step.
- **Files:** `vinu_stock/query/indicators.py`

### P1.5 — `_discover_first_year` probes provider APIs unnecessarily
- **Issue #7:** Always probes APIs even if catalog has first_bar_ts
- **Fix:** Before calling `_discover_first_year`, check if the symbol already has `first_bar_ts` in the catalog entry.
- **Files:** `vinu_stock/backfill/orchestrator.py`

## Phase 2 — Storage & I/O

### P2.1 — `write_bars` full-file rewrite
- **Issue #1:** Backfill writes entire year file on every run
- **Fix:** `append_bars` already uses daily files (good). For backfill (runs once per year per symbol), this is acceptable — document the trade-off. Alternatively, use DuckDB `COPY` to append row groups.
- **Files:** `vinu_stock/storage/parquet.py`

### P2.2 — Polygon `earliest_available` fetches billions of bars
- **Issue #8:** Fallback probes 1m data from 1990 (~10M+ rows)
- **Fix:** Change fallback probe to use `interval="1d"` (daily) instead of `"1m"`. Daily bars from 1990 is ~13k rows.
- **Files:** `vinu_stock/providers/polygon.py`

## Phase 3 — Code Quality & Consistency

### P3.1 — Race condition in `upsert_symbol`
- **Issue #15:** SELECT-then-INSERT race causes `IntegrityError`
- **Fix:** Replace SELECT-then-INSERT/UPDATE with `INSERT INTO ... ON CONFLICT DO UPDATE` (SQLite UPSERT).
- **Files:** `vinu_stock/catalog/store.py`

### P3.2 — Schema migration not thread-safe
- **Issue #16:** Two processes can both `ALTER TABLE ADD COLUMN` and one fails
- **Fix:** Wrap each `ALTER TABLE ADD COLUMN` in try/except for `sqlite3.OperationalError` (ignore "duplicate column").
- **Files:** `vinu_stock/catalog/store.py`

### P3.3 — `update_bar_range` → `upsert_symbol` double query
- **Issue #9:** Two SQL queries per symbol update
- **Fix:** Add an overload parameter `existing_entry` to `upsert_symbol` to skip the re-fetch inside it.
- **Files:** `vinu_stock/catalog/store.py`

### P3.4 — N SQL queries for N symbols in live ingest
- **Issue #10:** Individual SQLite query per symbol in loop
- **Fix:** Batch-load all symbols at once via `catalog.list_symbols()` into a dict before the loop.
- **Files:** `vinu_stock/live/ingest_cycle.py`

## Phase 4 — Provider Retry & Security

### P4.1 — API key in Polygon URL query string
- **Issue #14:** API key exposed in URL query string (logged by proxies)
- **Fix:** Move `apiKey` to `Authorization: Bearer` header.
- **Files:** `vinu_stock/providers/polygon.py`

### P4.2 — Standardize HTTP retry across providers
- **Issue #12/13:** Only Yahoo has retry; Alpaca/Polygon fail immediately
- **Fix:** Make Alpaca and Polygon use `http_get_with_retry` (from `retry.py`), consistent with Yahoo.
- **Files:** `vinu_stock/providers/alpaca.py`, `vinu_stock/providers/polygon.py`

### P4.3 — Exception type abuse in retry
- **Issue #23:** HTTP errors raised as `ConnectionError`
- **Fix:** Define a custom `TransientProviderError` (or use `requests.HTTPError`) instead of raising `ConnectionError` for HTTP 429/5xx.
- **Files:** `vinu_stock/providers/retry.py`

---

## Phase 5 — Server & API

### P5.1 — Backfill blocks HTTP server
- **Issue #17:** Synchronous backfill blocks FastAPI
- **Fix:** Run backfill in a background thread (`threading.Thread` or `asyncio.to_thread`). Return a job ID; provide a `/backfill/status/{job_id}` endpoint.
- **Files:** `vinu_stock/server/routes_config.py`

### P5.2 — No rate limiting on trigger endpoints
- **Issue #18:** Client can hammer trigger endpoints
- **Fix:** Add a simple in-process lock (or `threading.Lock`) to prevent concurrent backfill/ingest runs. Return 409 Conflict if already running.
- **Files:** `vinu_stock/server/routes_config.py`

---

## Phase 6 — Minor Fixes

### P6.1 — `_symbol_to_yahoo` dead code
- **Issue #11:** Function returns identical string regardless of branch
- **Fix:** Remove the function or implement actual Yahoo-specific mapping (e.g., BRK.B → BRK-B).
- **Files:** `vinu_stock/providers/yahoo.py`

### P6.2 — `has_adj_data` only checks Yahoo
- **Issue #19:** Flag ignores Polygon/Alpaca adjusted data
- **Fix:** Remove the `provider_id == "yahoo"` guard; check `adj_factor != 1.0` unconditionally.
- **Files:** `vinu_stock/backfill/year_job.py`

### P6.3 — `interval` column is dead data
- **Issue #20:** Column always `"1m"`, never queried
- **Fix:** Remove the column or add a comment that it is reserved for future use. Update `SymbolCatalogEntry` if column is removed.
- **Files:** `vinu_stock/catalog/schema.sql`, `catalog/store.py`

### P6.4 — Polygon accepts but ignores `interval` param
- **Issue #25:** Parameter accepted but URL always requests 1/minute
- **Fix:** Raise `ValueError` if `interval != "1m"`.
- **Files:** `vinu_stock/providers/polygon.py`

### P6.5 — DuckDB cursor never closed (Issue #22)
- **Status:** Already handled — `conn.close()` is called in the `finally` block at `engine.py:76`. No fix needed.

### P6.6 — Indicators recomputed on every HTTP request (Issue #5)
- **Status:** Deferred — would benefit from DuckDB SQL pushdown or a Redis cache layer. Low priority versus other fixes.

### P6.7 — Double copy in `_bars_to_table` (Issue #21)
- **Status:** Already uses vectorized `pa.array([getattr(b, name) for b in bars], type=typ)` — the issue description is outdated. No fix needed.
