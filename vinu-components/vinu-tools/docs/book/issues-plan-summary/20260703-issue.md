# Code Audit — 2026-07-03

## Critical

### 1. Race condition: `claim_next_pending` + `mark_running` not atomic
- **File:** `vinu_features/storage/sqlite_backend.py:190-202`
- **Problem:** `claim_next_pending` reads the next pending request, then `mark_running` updates it later. Between the two operations another worker can claim the same request.
- **Fix:** Use `UPDATE ... WHERE status = 'pending' LIMIT 1 RETURNING *` for an atomic claim (SQLite supports this in recent versions).

### 2. `check_same_thread=False` is unsafe
- **File:** `vinu_features/storage/sqlite_backend.py:55`
- **Problem:** SQLite connections are not thread-safe. Disabling the check allows sharing the connection across threads, risking race conditions on reads/writes.
- **Fix:** Use a thread-local connection or connection pool with `check_same_thread=True`.

### 3. Sequential per-symbol HTTP fetches — no parallelism
- **File:** `vinu_features/engine/engine.py:58-73`
- **Problem:** For each symbol the engine fetches candles synchronously before processing. 100 symbols = 100 serial HTTP calls.
- **Fix:** Use `concurrent.futures.ThreadPoolExecutor` to parallelize symbol fetching.

### 4. Monkey-patching module attribute for DI
- **File:** `vinu_features/server/app.py:34`
- **Problem:** `routes_requests.get_service = _get_service` mutates the module at runtime, invisible to type checkers and hard to reason about.
- **Fix:** Use proper FastAPI dependency injection with `Depends()`.

### 5. Silent type coercion on feature params
- **File:** `vinu_features/compute/feature_spec.py:51`
- **Problem:** `int(val)` is called after `re.fullmatch(r"-?\d+", val)` fails on floats like `"20.5"`. The value falls through to `float(val)`, then `validate_params` calls `int(20.5)` → `20`. Silent truncation with no error.
- **Fix:** Check `isinstance(raw, float)` when `pdef.type == "int"` and raise.

## Performance

### 6. `rolling_std` is O(n×w) instead of O(n)
- **File:** `vinu_features/compute/indicators/_shared/rolling.py:34-43`
- **Problem:** For each position `i`, it computes `sum(window) / period` and then `sum((x-mean)**2)`. This is O(n×period).
- **Fix:** Use incremental variance update (Welford's method).

### 7. All alpha rolling functions use naive O(n×w) Python loops
- **File:** `vinu_features/compute/bigger_recipe/_alpha_expr/evaluator.py:111-128`
- **Problem:** `_rolling_apply`, `_rank`, `_quantile`, `_slope`, `_rsquare`, `_resi`, `_idxmax`, `_idxmin`, `_corr` all loop per-position and slice the array. With 101 formulas on 10,000 rows this is millions of Python-level iterations.
- **Fix:** Vectorise with NumPy sliding window or `numba`.

### 8. Eager import of all 23 indicator modules at startup
- **File:** `vinu_features/compute/registry.py:11-15`
- **Problem:** `importlib.import_module` runs at import time for every indicator, slowing every CLI command even when only one indicator is needed.
- **Fix:** Lazy-load individual modules on demand.

### 9. Eager import of all 9 ML models at startup
- **File:** `vinu_features/compute/ml_models/registry.py:8-22`
- **Problem:** Importing all sklearn-based models at module level slows every CLI command, even `vinu-features features list`.
- **Fix:** Lazy-load individual model modules.

### 10. Redundant sort on already-sorted API data
- **File:** `vinu_features/engine/engine.py:118-125`
- **Problem:** `out.sort(key=lambda r: r["ts"])` sorts all rows after normalisation. API data is typically already sorted by timestamp.
- **Fix:** Check if already sorted, or trust the API.

### 11. Feature name iteration per-row in `_rows_to_table`
- **File:** `vinu_features/engine/engine.py:128-138`
- **Problem:** For each row, the inner loop does `row.get(feat)` for every feature. For 100 features × 10,000 rows = 1M dict lookups.
- **Fix:** Pre-extract row values or use `pa.RecordBatch.from_pylist`.

### 12. `_normalize_rows` field lookup is O(n) per row for known keys
- **File:** `vinu_features/engine/engine.py:110-111`
- **Problem:** `row.get("ts") or row.get("timestamp") or row.get("sort_ts")` checks three keys per row. The keys are known at call time.
- **Fix:** Determine the correct key once outside the loop.

### 13. `_ref` allocates `np.full_like` on every call
- **File:** `vinu_features/compute/bigger_recipe/_alpha_expr/evaluator.py:79-88`
- **Problem:** Each call to `Ref()` creates a new full array. With 101 alpha formulas × many `Ref` calls this is memory-intensive.
- **Fix:** Cache or pre-allocate the sentinel array.

## Design & Maintainability

### 14. Huge `if/elif` chain with repeated `with FeatureService()` in CLI
- **File:** `vinu_features/cli.py:106-209`
- **Problem:** Every subcommand branch has `with FeatureService() as service:` repeated. Violates DRY.
- **Fix:** Extract common pattern to a helper function.

### 15. Union return types force `isinstance` checks everywhere
- **File:** `vinu_features/compute/feature_spec.py:28,55`
- **Problem:** `_parse_spec_string` and `parse_feature_input` return `FeatureSpec | str`. Callers must `isinstance` check before use.
- **Fix:** Use a dedicated type (e.g., `RecipeRef`) or separate parse/resolve phases.

### 16. Giant if/elif switch for warmup bars
- **File:** `vinu_features/compute/indicators/_shared/spec.py:64-88`
- **Problem:** Each new indicator requires a new branch. Violates Open/Closed principle.
- **Fix:** Use each module's `WARMUP_BARS` attribute as the source of truth.

### 17. Hardcoded feature names instead of deriving from metadata
- **File:** `vinu_features/compute/registry.py:73-78`
- **Problem:** Names like `"rsi_14"`, `"macd"` are hardcoded strings. Adding a new indicator requires updating this list.
- **Fix:** Derive from `INDICATOR_MODULE_NAMES` + metadata.

### 18. `warmup_bars_for_features` redundantly calls `_alpha_name_sets()` per feature
- **File:** `vinu_features/compute/registry.py:86-99`
- **Problem:** The triple set (alpha101, alpha158, alpha360) is fetched on every loop iteration.
- **Fix:** Compute once before the loop.

### 19. `MockCandleClient` duplicated across 4 test files
- **Files:** `tests/test_api.py`, `tests/test_engine.py`, `tests/test_feature_spec.py`, `tests/test_worker.py`
- **Problem:** The same mock class defined identically in four places.
- **Fix:** Move to `tests/conftest.py`.

### 20. `test_presets.py` uses `try/except/else` instead of `pytest.raises`
- **File:** `tests/test_presets.py:22-26`
- **Problem:** Non-idiomatic pattern.
- **Fix:** Use `with pytest.raises(ValueError, match="nope"):`.

### 21. `parse_feature_names([preset])` called for side-effect only
- **File:** `vinu_features/service.py:82`
- **Problem:** Return value is discarded. It's unclear that this is just validation.
- **Fix:** Use an explicit validation call.

### 22. `_apply_env_overrides` mutates global `os.environ`
- **File:** `vinu_features/cli.py:24-27`
- **Problem:** Side effect persists for the process lifetime and affects other tests / commands.
- **Fix:** Pass configuration explicitly rather than through env vars.

### 23. `load_dotenv()` at module import time
- **File:** `vinu_features/config.py:11`
- **Problem:** Importing anything from `vinu_features` mutates global `os.environ`.
- **Fix:** Move `load_dotenv()` inside `load_config()`.

### 24. `port = int(os.getenv(...))` will throw non-informative `ValueError`
- **File:** `vinu_features/config.py:24-32`
- **Problem:** If env var is `"abc"`, the error doesn't say *which* variable failed.
- **Fix:** Wrap in `try/except` with a clear message.

### 25. `format_help` param parsing fails on negative numbers / scientific notation
- **File:** `vinu_features/compute/feature_catalog.py:106-108`
- **Problem:** `.isdigit()` returns `False` for `"-1"` and `"1e-5"`.
- **Fix:** Use `try: int(v) except ValueError: float(v)`.

### 26. Late imports inside function bodies (inconsistent style)
- **Files:** `vinu_features/cli.py:186`, `vinu_features/compute/feature_spec.py:94`, `vinu_features/server/routes_features.py:21`
- **Problem:** Suggests circular import concerns. Inconsistent with module-level imports used elsewhere.
- **Fix:** Restructure to eliminate circular dependencies.

### 27. `FeatureSpecIn.params` accepts `str` values but backend only handles `int | float`
- **File:** `vinu_features/server/schemas.py:12`
- **Problem:** `dict[str, int | float | str]` — if a `str` slips through, `validate_params` fails with unclear error.
- **Fix:** Remove `str` from the union or add server-side validation.

### 28. `indicator_meta_to_dict` returns plain `dict` — no type safety
- **File:** `vinu_features/compute/feature_catalog.py:125`
- **Problem:** Callers lose all type information.
- **Fix:** Use a `TypedDict` or dataclass.

## SQL / Storage

### 29. Schema migration via `ALTER TABLE` in a loop with silent ignore
- **File:** `vinu_features/storage/sqlite_backend.py:58-62`
- **Problem:** Migration tries `ALTER TABLE` and silently catches `OperationalError`. Doesn't scale as columns are added.
- **Fix:** Track schema version explicitly.

### 30. SQL built via string concatenation
- **File:** `vinu_features/storage/sqlite_backend.py:177-188`
- **Problem:** `f"""...WHERE {where}...LIMIT ?"""` — while `where` is built from validated inputs, the pattern is fragile.
- **Fix:** Use a query builder or parameterised column names via a whitelist.

### 31. No WAL mode for concurrent writes
- **File:** `vinu_features/storage/sqlite_backend.py`
- **Problem:** Default journal mode causes write contention for concurrent workers.
- **Fix:** Set `PRAGMA journal_mode=WAL` on connection.
