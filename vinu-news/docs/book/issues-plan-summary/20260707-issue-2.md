# LLM vs Rule-Based Enrichment — Decision Record

## Background

Two enrichment layers exist in the vinu-news pipeline:

1. **Rule-based** (VADER + financial lexicon + impact rules) — runs on every article, free, fast
2. **LLM** (Ollama) — runs on current news (optional), slower, captures deep context

This document captures when each is appropriate and why we keep both.

---

## What Rule-Based Can Do Well (90%+ accuracy)

| Task | Quality | How |
|------|:---:|-----|
| Sentiment (bullish/bearish/neutral) | ✅ | Financial language is formulaic: *"upgrade", "buy rating", "missed estimates", "SEC probe"* all map cleanly to a lexicon |
| Impact score | ✅ | Already computed from actual post-article price movement — LLM has no advantage here |
| Category tagging | ✅ | *"earnings"* → `EARNINGS`, *"dividend"* → `DIVIDEND`, *"merger"* → `M&A` |
| Ticker extraction | ✅ | Simple regex + watchlist match |
| Threat classification | ✅ | Keywords cover 85%+ of cases |

## What Rules Fundamentally Cannot Do

| Task | Why rules fail |
|------|---------------|
| **Novel/unknown risks** | No keyword list catches something like *"Apple's new chip has a vulnerability that..."* when the vulnerability name is new |
| **Context-dependent sentiment** | *"The company reported a loss, but it was better than expected"* — VADER sees "loss" and scores negative; LLM reads the full sentence and scores positive |
| **Confidence calibration** | Rules give a blind score; LLM can signal uncertainty: *"60% confident bearish — language is mixed"* |
| **Narrative summary** | Rules generate zero text; we rely on source-provided `summary` field |
| **Entity relationships** | Rules extract tickers but can't explain *how* entities relate to each other |

## The Gap: ~5-10% of articles

The rule-based system misclassifies roughly 5-10% of articles where tone inversion, sarcasm, or non-obvious context matters. The LLM catches these but at a cost (Ollama runtime, GPU memory).

## Decision

| Data source | Enrichment | LLM? |
|-------------|-----------|:----:|
| **RSS current news** (live stream, ~50-200/day) | Full pipeline | ✅ Optional (auto or manual) |
| **Alpaca historical backfill** (thousands/ticker) | Rule-based only | ❌ Skip — volume too high, formulaic |
| **High-impact historical articles** (user-selected) | On-demand deep analysis | ✅ Only when explicitly triggered |

## Future: Price-Calibrated Sentiment

A third layer planned for later: adjust rule-based sentiment scores based on *actual* post-article price movement (computed during correlation pass). This gives a feedback loop:
- Article scored neutral by VADER → price dropped 3% → mark as *de facto* bearish
- Over time, build a correction model that learns which words are *actually* bullish/bearish for this specific ticker

This further reduces reliance on LLM for bulk processing.

## Summary

| Layer | Speed | Accuracy | Coverage | Cost |
|-------|:----:|:--------:|:--------:|:----:|
| VADER + Fin Lexicon | Instant | 90-95% | 100% | Free |
| Price-Calibrated (future) | Instant | 93-97% | 100% | Free |
| LLM (Ollama) | 1-5s/article | 97-99% | Optional | GPU/CPU |

We keep all three. Each fills a gap the other cannot.
