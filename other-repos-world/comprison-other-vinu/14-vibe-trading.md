## Advanced Features

- **Five-layer ReAct context-management pipeline** (`agent/loop.py`) — a genuinely sophisticated answer to "how does a long-running agent not blow its context window": Layer 1 (microcompact) prunes old tool results under memory pressure; Layer 2 (context_collapse) folds long text blocks with zero LLM cost; Layer 3 (auto_compact) does an LLM structured summary with token-budget tail protection; Layer 4 lets the model explicitly trigger Layer 3 via a `compact` tool; Layer 5 makes the Nth compression *update* the previous summary instead of starting fresh. Each layer is a distinct, named, escalating strategy, not one blunt truncation.
- **Grounding ledger — a deterministic, non-LLM validation gate on the agent's final answer** (`agent/grounding.py`) — three facts are checked mechanically, not left to the model's discretion: (1) a market-data identity may only be used if it was locked before the current tool-call batch started, (2) a final price claim may not contradict the full, untruncated tool result, (3) a figure may not be attached to an instrument no tool call in the run ever returned. Explicitly designed to be dependency-free (no provider/tool-registry imports) so it stays deterministic and testable — a structural anti-hallucination gate, not a prompt instruction hoping the model behaves.
- **Hash-chained, fsynced, append-only audit ledger** (`governance/ledger.py`) — each record embeds `seq` and `prev_record_hash`; because every record folds in its predecessor's hash, editing or deleting *any* earlier record breaks every record chained after it. Explicitly built to replace a bare `open(path,"a").write()` audit path that had no fsync, no sequencing, and no tamper detection. `src/live/audit.py` wires it in as an opt-in `chain=True` mode, writing to a separate file from the plain audit log rather than retrofitting it.
- **A near-exact structural analog to Vina's own OrderGuard/TradingMandate, independently arrived at** — `live/mandate/`, `live/order_guard.py`, `live/halt.py`, `live/daily_count.py`, `live/enforcement.py`. `LiveOrderGuardTool.execute()` runs, in order, all fail-closed: mandate validity → consent expiry → halt-flag check → order-intent parsing → live position/balance read → `check_mandate` (ALLOW / DENY / **PAUSE_FOR_REAUTH**). Two parallel gate implementations exist for the same ceremony — one wrapping MCP remote tools (`order_guard.py`), one for direct-SDK connectors like Alpaca (`sdk_order_gate.py`) — sharing identical fail-closed semantics.
- **Notional sizing enforced as the LARGER of explicit notional and `quantity × price`**, fail-closed DENY when no quote is obtainable at all — closes a specific underestimation gap (a quantity-only order without an explicit dollar cap slipping past a notional check).
- **Mandate consent has a time-boxed expiry** (`consent.expires_at`) that routes to re-authentication when past, not just a static always-valid config.
- **`PAUSE_FOR_REAUTH` as a third outcome beyond ALLOW/DENY** — quantitative limit breaches (as opposed to structural ones like an unknown instrument/universe) pause for human re-authorization rather than hard-denying outright — a middle ground between "let it through" and "reject it."
- **Strategy-discovery evidence gate, fail-safe by design** (`strategy_discovery/guard.py`) — the routing text advertising `list_strategies`/`query_strategies`/`get_strategy_evidence`/`refresh_strategy_evidence` to the agent is only emitted when *all four* tools are actually registered — atomic advertisement, specifically to prevent the agent being told about a tool it then can't call (cites a specific prior incident, "the rejected #896"). The routing text itself instructs: "NEVER present insufficient or marginal evidence as a recommendation."
- **Swarm worker as a deliberately separate, lightweight ReAct loop** (`swarm/worker.py`) — explicitly does *not* instantiate the main `AgentLoop`, using `ChatLLM.chat` directly in a manual for-loop instead, "keeping the worker self-contained and the agent core unchanged" — an explicit design choice to avoid coupling parallel/background agents to the main loop's complexity.

## Why It's Trusted / Mature

Vibe-Trading earns trust through a specific, recurring pattern across every subsystem examined: **structural, mechanically-checked guarantees instead of instructions hoped the model follows.** The grounding ledger doesn't ask the LLM to cite sources correctly — it checks the final answer against tool-call evidence after the fact, deterministically. The strategy-discovery guard doesn't trust that the prompt-writer remembered to register all four tools — it checks at runtime and fails safe. The hash-chained ledger doesn't trust that a log file wasn't edited — it makes tampering detectable by construction. This is a meaningfully different posture from most of the 13 originally-audited repos, several of which (FinceptTerminal's 37 "AI agents," most LLM re-rank patterns) treat the LLM's output as the answer, full stop. Vibe-Trading treats the LLM as a fallible component wrapped in deterministic checks — closer in spirit to how `vinu-agent`'s own OrderGuard already treats order decisions, just extended further into the LLM-output-verification space than Vina currently goes.

## vs Vinu — Gap & Adoptable Logic

**Gap:** Vina's `vinu-agent` has a real, working OrderGuard/TradingMandate chain (14 checks, confirmed by direct trace this session), but nothing that mechanically validates the *content* of an LLM-generated research thesis against the tool evidence that produced it — a hallucinated price or a stat attached to the wrong symbol in a generated strategy artifact would not be caught by anything in Vina's current pipeline the way the grounding ledger catches it here. Vina also has no cryptographic tamper-evidence on its audit trail — kill-switch/halt/order events are presumably logged, but nothing hash-chains them the way `governance/ledger.py` does. And Vina's mandate has no consent-expiry/re-auth concept — a mandate loaded once stays valid indefinitely, with no equivalent to `PAUSE_FOR_REAUTH` for a borderline quantitative breach.

**Adopt:**
- **The grounding-ledger pattern** — port the core idea (not the exact code) into `vinu-research`'s artifact-generation path: after an LLM produces a research thesis/trade-plan, mechanically verify every numeric claim and instrument reference traces back to an actual tool call made during that generation run, before the artifact is persisted. This is a strong, structural complement to the deflated-Sharpe/holdout/stress-test gate — that gate validates the *strategy*, this would validate that the *thesis text describing it* isn't hallucinated.
- **Hash-chained audit ledger** — apply to Vina's kill-switch/halt/emergency-flatten event log. These are exactly the "explain what happened after something went wrong" events where tamper-evidence matters most, and it's a small, self-contained primitive (the module is explicitly domain-agnostic and dependency-light per its own docstring).
- **`PAUSE_FOR_REAUTH` as a third OrderGuard outcome** — Vina's 14-check chain is currently binary per check (pass/reject). Consider whether a "quantitative, borderline" breach (e.g. an order at 95% of `max_order_value`) should route to a human-confirmation pause rather than a flat reject — this is a different, softer failure mode than the existing `require_confirmation` gate, which is unconditional rather than breach-triggered.
- **Notional-sizing "larger of explicit notional and quantity × price, fail-closed on unpriceable"** — cross-check `OrderGuard`'s `max_order_value` check (`order_guard.py:136-141`, per the earlier lifecycle trace) actually enforces this same larger-of logic, not just the explicit order value as submitted.
- **Mandate consent expiry** — worth considering whether `TradingMandate` should carry an expiry/re-load-and-reconfirm cadence, rather than being loaded once and trusted indefinitely for the life of the process.
- **The five-layer context-management pipeline** — most directly relevant if `vinu-agent`'s ReAct loop (or a future `vinu-screener`'s LLM re-rank step, if one is added per the DSA-inspired design) runs long multi-tool-call sessions; the escalating-strategy shape (cheap prune → cheap fold → LLM summary → explicit trigger → incremental update) is a well-reasoned reference architecture worth comparing against whatever context management `vinu-agent` currently has.

## Where Vinu Excels

- **A statistically rigorous promotion gate before a strategy trades.** Vibe-Trading's strategy-discovery layer gates *recommendations* on evidence sufficiency (`query_strategies` refuses to present insufficient evidence as a recommendation), but nothing found in this repo resembles `vinu-research`'s deflated-Sharpe + holdout + stress-test + PBO gate — it's evidence-presence checking, not overfitting-correction statistics.
- **A single, coherent live-trading risk architecture**, not two parallel gate implementations. Vibe-Trading needs `order_guard.py` (MCP-wrapped) and `sdk_order_gate.py` (direct-SDK) as separate code paths with duplicated ceremony because it supports many brokers via two different integration styles; Vina's single-broker (Alpaca) focus means `OrderGuard` is one code path, one thing to keep correct, by design.
- **Purpose-built as a narrow, focused trading system**, not a broad personal-agent platform. Vibe-Trading's scope (swarm workers, goal/governance/hypotheses subsystems, multi-broker MCP+SDK support, a full frontend) is considerably wider than Vina's; that breadth is exactly why the LLM-agent core is so sophisticated, but it also means Vina's tighter scope lets it harden the specific equities/Alpaca/LLM-research path more deeply per unit of engineering effort than a platform this broad can for any one path.
