# Third Code Audit — vinu-simulator

**Date**: 2026-07-06  
**Scope**: Zero-state and boundary-condition edge cases missed in cycles 1 and 2

## Critical Issues

### ZC1. `SimulatorEnv.step()` missing NaN/Inf guards — same vulnerabilities as C2

**File**: `vinu_simulator/engine/simulator.py`, lines 282, 300, 309, 312, 327, 329, 348-353  
**Problem**: Cycle 2 fixed NaN/Inf propagation in `WeightSimulator.run()` but `SimulatorEnv.step()` has the identical vulnerabilities. Prices can contain NaN/Inf, zero prices cause Inf shares, and invalid values propagate silently.

| Location | Problem |
|----------|---------|
| Line 282 | `prices = ...values.astype(np.float64)` — no `np.isfinite(prices)` check; NaN prices enter simulation |
| Line 300 | `deviation = ...` — no `np.isfinite(deviation)` check; NaN deviation is silently `False`, rebalance skipped |
| Line 309 | `shares_to_sell = -delta * nav_before / prices[idx]` — no `prices[idx] <= 0` guard; zero price → Inf shares |
| Line 312 | `if shares_to_sell <= 1e-12: continue` — executed **before** a finite check; `Inf <= 1e-12` is `False`, Inf trades execute |
| Line 327 | `target_shares = target_values[idx] / prices[idx]` — no `prices[idx] <= 0` guard; zero price → Inf |
| Line 329 | `shares_to_buy <= 1e-12` comparison before finite check |
| Lines 348-353 | `with np.errstate(divide="ignore", invalid="ignore")` — intentionally silences warnings, same pattern removed from `run()` in cycle 2 |

## High Issues

### ZH1. Division by zero in metrics when initial portfolio value is zero

**File**: `vinu_simulator/engine/metrics.py`, line 36  
**Problem**: `cumulative = portfolio_values / portfolio_values.iloc[0]` — when `portfolio_values.iloc[0] == 0` (e.g. zero initial capital), this produces `Inf/NaN`. All downstream metrics (max_drawdown, drawdown_series, calmar) are silently corrupted.

### ZH2. `FlatCostModel.sell_proceeds` returns negative for extreme slippage

**File**: `vinu_simulator/engine/costs.py`, line 54  
**Problem**: `effective_price = price * (1 - self.slippage_pct)` — when `slippage_pct > 1.0`, `effective_price` is negative and `sell_proceeds` returns negative (the seller pays to exit). `AlmgrenChrissCostModel.sell_proceeds` was clamped in M9 but `FlatCostModel` was not.

### ZH3. `_result_dir` creates directory tree on read operations

**File**: `vinu_simulator/storage/results.py`, lines 37-40  
**Problem**: `_result_dir()` calls `p.mkdir(parents=True, exist_ok=True)` and is used by both save and load methods. Read operations (`load_equity`, `load_weights`, `load_trades`) silently create empty directory artifacts.

## Medium Issues

### ZM1. Empty `total_calendar` with dual-empty inputs

**File**: `vinu_simulator/engine/simulator.py`, lines 68, 97  
**Problem**: If both `price_data` and `weight_signals` are empty DataFrames (defensive edge case), `total_calendar = price_data.index.union(weight_signals.index)` is empty, and the for loop on line 97 iterates zero times. Returns a `SimulationResult` with empty series, which downstream callers may not handle gracefully.

### ZM2. No context manager on `SimulatorAPI`

**File**: `vinu_simulator/api.py`, lines 10-58  
**Problem**: `SimulatorService` has `__enter__`/`__exit__` (M13), but `SimulatorAPI` does not. CLI commands in `cli.py` create `SimulatorAPI()` without calling `.close()`, leaking HTTP clients and SQLite connections on every CLI invocation.

## Low Issues

### ZL1. Zero-price edge cases in Almgren-Chriss model

**File**: `vinu_simulator/engine/costs.py`, lines 79, 96, 108  
**Problem**: `price * shares * coeff * (rate ** exp)` — if `price` is 0, `_market_impact` returns 0 (correct). But `buy_cost` computes `effective_price * shares + fixed + impact` where `effective_price` is also 0 and `fixed` is 0, so `buy_cost` returns 0. A zero-price buy costs nothing, which is correct but worth noting.
